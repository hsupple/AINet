AINet Database Rules
====================

These rules are READ-ONLY for the AI. Only a human (or privileged setup code) may edit this file.

1. Sandbox
   - All AI filesystem tools operate only under the database root (`db/`).
   - Path traversal outside the database root is forbidden.
   - The PC that runs Ollama and these database tools is a Windows machine.
   - All paths inside the database use forward slashes (`hayden.json`, `Projects/BOMB/project.json`) even on Windows.
   - Never use drive letters, UNC shares, or backslash-only absolute paths in tool calls.

2. Protected files
   - Rules.txt: AI may read. AI must never write, rename, move, or delete.
   - Calendar.json: AI may read. Writes are code-only (scheduler/system), never AI tools.
   - Changelog.json: pending OAC→SOI queue only. AI must not rewrite. Tool writes and filed/discarded turns are appended to Masterlog.json (kept forever).
   - Masterlog.json: append-only permanent archive of filed/discarded oac_turns. Never delete or rewrite. AI may read.

3. Flat knowledge files
   - Personal knowledge lives in a handful of JSON files at db/ root — not nested folders.
   - Each file (and each hayden.json section) is a map of named keys to observation lists:
       "Name": [{"time": "...", "text": "..."}]
     SOI log_item creates the key if missing, then appends. Do not use items[].
   - count and strength are host-computed. Strength is linear decay: remaining = 1 - age/lifetime.
     lifetime interpolates from low_days (1 mention) to high_days (5+ mentions). Tune in Folderrules.json decay.
     When remaining drops below floor (0.05), the host deletes that observation; empty/dead keys are removed.
     secrets.json decays on query but is never auto-deleted.
   - OAC retrieves with query_db (name, words, after/before/since_days). Do not dump whole files first.
       hayden.json     — who Hayden is: characteristics, preferences, habits, values, desires, body, psychology (each a name→list map)
       people.json     — people keyed by name
       questions.json  — topics keyed by name
       household.json  — home, pantry, repairs
       memories.json   — life events
       secrets.json    — private vault
       Projects/<Name>/project.json — named projects (the only folders besides host runtime)
       Calendar.json   — upcoming calendar (code-only writes). There is no planner.json.
   - Do not invent extra personal folders. Projects/<Name>/ is the exception (plus Files/ inside a project).

4. Dual AI roles
   - AI1 OAC (Orchestrator of Conversation): live interface. READ tools + web_search/web_fetch/spotify.
     Short-term chat lives in db/Chats/ (host-owned). OAC cannot use general DB writes.
     Retrieval: query_db (name, words, dates). read_json is for dumping a whole file when needed.
   - Every OAC user turn is stacked onto Changelog.json as action=oac_turn with user_text and soi_status=pending.
     After SOI files or discards it, the host appends that entry to Masterlog.json and drops it from the Changelog queue.
   - AI2 SOI (Slave of Information) files pending oac_turns after OAC idle (soi_idle_seconds, default 180s).
       One tool: log_item(dest, label, reason, entry_id).
       label is the key (person name, trait, topic). Host creates "Name": [] if missing, then appends {time, text}.
       dest is one of: hayden, preferences, habits, values, desires, body, psychology, people, questions, household, memories, secrets, discard, or a project name.
       Near-term schedule/todos are dest=discard until Calendar exists.
       Reuse an existing key when it is the same person/trait/topic (see the labels list in the batch).
       Split a turn: people AND feelings AND a want → three log_item calls, same entry_id, different dest/label.
       Discard greetings and acknowledgment-only turns.
       Host only marks soi_status filed/discarded when log_item actually ran (or dest=discard).
   - SOI state lives under db/runtime/soi/. OAC must not mutate the personal DB.

5. Secrets
   - secrets.json is a private vault. The AI may read it to understand Hayden.
   - Default: use secrets for understanding; do NOT volunteer secret contents in spoken output.
   - Only name or narrate a secret if Hayden explicitly asks, or if withholding it would cause clear harm/safety issues.

6. Structure
   - Respect Folderrules.json for naming and allowed create locations.
   - Domain knowledge files at db/ root must not be deleted or renamed by the AI.
   - db/runtime/ is host-owned short-term state (OAC sessions, SOI cursor, Spotify tokens).
   - db/Chats/ is the host-owned chat log. AI tools cannot read or write it.

7. Mutations
   - SOI files only via log_item. Do not patch_json/write_json the knowledge files.
   - Inside a focused project, OAC may create subfolders and text files under Projects/<Name>/ only.
   - Every successful mutating tool call is archived to Masterlog.json.
   - Never invent nested Hayden/School/Work/Household trees. Those are gone.

8. Honesty
   - If a tool call is denied, say so. Do not pretend the database changed.

9. Internet search (Brave)
   - Tools: web_search (Brave Search API) and web_fetch (plain-text URL fetch). Available to OAC
     (read-only live) and SOI (log_item only — SOI does not search).
   - API key: set environment variable BRAVE_API_KEY or AINET_BRAVE_API_KEY.
   - Windows: set via System Environment Variables, or in PowerShell for the session:
       $env:BRAVE_API_KEY = "your_token_here"
